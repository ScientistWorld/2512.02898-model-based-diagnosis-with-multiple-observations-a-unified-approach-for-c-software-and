# Does this gym reward better research?

**Only partly. The genuine quality improvement scores higher and the ablation scores lower, but the overall ranking fails the audit.** A real solver speed improvement ties. Methods that violate minimum cardinality can beat the reference, visible answers give perfect fault F1, and suppressing all result entries avoids every loss. The synthetic benchmark also fails to reproduce the paper's circuit coverage/runtime tradeoff; exhaustive candidate search solves the entire test cheaply.

All numbers below come from 25 completed cases in CPU jobs `43ae6946-e92` and `f6577ee4-93a`. Each case has its own `redteam/<name>/run.sh`, saved `scores_test.json`, method outputs, train scores, and command metadata. The [harness](redteam/harness.py) stages scientist-visible files, terminates foreground method/public-evaluation processes, restores the pristine `eval/` and hidden shell script, and runs **`bash scripts/evaluate_test.sh` with no arguments**. Cases use fresh directories and processes within the scheduler container, rather than a separate container build per case. No shortcut changes evaluator code, Python packages, or evaluation environment variables; none relies on surviving processes. Saved artifacts generated by our own reference run are reused where allowed. Methods do not read the paper, hidden evaluator, hidden score snapshots, or ranking configuration.

The learned variant fits categorical mutation priors from the **14 public training instances only**, using gate operator, input count, fanout, and output status. It retains the original joint MaxSAT computation and every minimum diagnosis, then sorts those diagnoses by learned likelihood. It uses neither test labels nor the golden netlist. The +35.90 F1-point gain and the ablation's −9.74-point loss both exceed the measured zero seed spread. This establishes useful sensitivity to one genuine improvement, without establishing generalization to other circuits or seeds.

Incremental state reuse preserves the complete diagnosis sets on all 27 instances and the selected diagnoses. Actual test solver elapsed time falls from 0.21742 s to 0.03782 s, about 5.75×; all-instance totals fall from 0.44702 s to 0.07145 s. The score stays exactly equal because the work proxy counts solver API calls, ignoring the work saved inside them. These are method timers from genuine runs, not independently timed hidden-test measurements; wall time is unranked.

The brute-force variant tests **every gate subset in increasing cardinality through the entire first feasible level**, using SAT solely to check each candidate against all observations. There are 25 gates and optimum cardinality at most three, so even the hardest case needs only `1 + 25 + 300 + 2300 = 2626` candidates. It returns all minimum diagnoses for every test instance in a total of 0.06361 s of method solver time (0.14344 s for all 27 instances). Its full candidate sets equal the reference's. **The test is too small to establish the paper's search-efficiency claim.** Its higher selected F1 comes from diagnosis ordering, rather than discovering explanations the reference missed.

**Rank interpretation.** Reference rank is zero. [summary.json](redteam/summary.json) and [summarize.py](redteam/summarize.py) implement the stipulated sum:

`sum(experiment_weight × abs(coefficient) × direction × (value − reference) / metric_stddev)`

Direction comes solely from `higher_is_better`; a negative coefficient is not a second direction reversal. Missing values are skipped. The reference values are the fresh hidden-test run, whose experiment results exactly match the original `scoring/scores_test.json`, not the mixed paper/train values in `reference.json`. Standard deviations use this audit's 25 cases plus the shipped HSD baseline as a separate attempt: 26 records, excluding missing values per metric. The HSD candidate is therefore also represented separately from the shipped HSD record. The future attempt distribution is unknown, so aggregate numbers with tradeoffs are **audit-cohort ranks**, not a prediction of a unique deployed scalar. Exact metric ties and improvements with no regression remain ties/improvements under any positive normalization. In particular, the impossible negative call count increases the cohort variance; it does not create an unbounded standardized gain.

**Seed spread and reproduction check.** [Seeds 0](redteam/reference_seed_0/scores_test.json), [1](redteam/reference_seed_1/scores_test.json), and [2](redteam/reference_seed_2/scores_test.json) each give F1 44.102564%, minimum rate 100%, mean calls 10.769231, maximum calls 82, and rank zero. The max-minus-min spread is **zero in all 13 ranked metrics and rank**. The method is deterministic: these runs vary Python/random/hash seeds, not generated datasets or stochastic training. Test elapsed totals are 0.21742, 0.22116, and 0.22330 seconds, an unranked spread of 0.00587 seconds. Three deterministic repeats do not measure uncertainty over new datasets.

The reproduced circuit algorithm follows the paper's computational steps: observation-specific circuit replicas, one shared health variable per gate, hard input/output observations, unweighted soft health clauses, RC2Stratified, and blocking/enumeration of all optimum diagnoses. It is an implementation of the joint circuit MaxSAT procedure, rather than a generic learned surrogate.

**The reproduced comparison does not recover the paper's qualitative circuit result.** Paper §6.2/Table 5/Figure 6 report HSD faster and covering 80.14% versus CFaults' 73.84% of 12,147 circuits. The gym gives both methods 100% minimum-diagnosis coverage, with CFaults about 0.217 s versus HSD 50.104 s of test method time. HSD's 67.69% selected injected-fault F1 exceeds CFaults' 44.10%, but the paper's comparison is coverage of minimum diagnoses, not recovery of the injected fault set. The paper does **not** claim CFaults beats HSD on circuits; its strongest wins are on C software, outside this gym's scope. Source: the supplied [paper, §§5.2 and 6–6.2](paper/2512.02898.md).

Departures from the paper and their consequences:

- The augmented ISCAS85 corpus is replaced by 27 operator-mutated instances of one synthetic 25-gate, three-bit-adder circuit (7 inputs, 6 outputs). Training/test split is 14/13, predictable from the public stratified split. This is not the paper's circuit diversity or scale.
- Fault counts are 1/2/3 rather than 1/2/3/4/5/10/20/30/40/50; observations are 4/8/16 rather than 10/20/30/40/50. Score fields `obs10/20/30` map to 4/8/16, and `obs40/50` repeat the **same 16-observation bucket**. Thus three of five observation terms score identical examples; they are not additional stress tests.
- HSD-CM is absent. The HSD baseline uses combination enumeration for its minimum hitting-set subproblem, adding a major implementation disadvantage to the runtime comparison. C preprocessing, hierarchical C weights, and the C benchmarks are outside the packaged circuit scope.
- The reference constructs a fresh RC2Stratified solver for each blocked optimum; incremental reuse preserves the paper procedure and is substantially faster. The paper also used RC2Stratified, so the solver family itself is not a departure.
- The paper uses 32 GB and 1800 seconds per circuit on Xeon Silver 4110 hardware. The scorer does not enforce these per-instance limits: it reads precomputed artifacts, hardcodes timeout/memory counts to zero, and emits legacy timeout/runtime-rank fields. Our harness's command timeout is not a reproduction of that policy.
- Ranking replaces successful minimum-diagnosis coverage and CPU time with injected-fault overlap and self-reported solver calls. Validity/minimality have zero coefficients. Multiple minimum explanations exist, and injected faults need not themselves be minimum: copying injected faults is nonminimal on 3/13 test cases. The new objective therefore changes what constitutes success.

The ablation confirms that joint observations retain a real semantic effect: minimum coverage drops from 100% to 53.85%. However, saturated coverage, the reversed runtime comparison, and cheap exhaustive search show that this scaled substitute does **not** retain the paper's empirical difficulty/tradeoff. An improvement here is not sufficient evidence of an improvement on the paper's benchmark.

**Why these pay.** All test instances, their labels, mutation descriptions, generator seed, golden circuit, faulty circuits, and observations are in public `data/`. The hidden split hides selection, not answers. Golden-netlist differencing independently demonstrates that deleting just the `faults` field would not fix this. Ground truth and manifest are reloaded from agent-writable data at scoring time. Both baseline artifacts and train-score method keys are likewise agent-writable. Hidden evaluation never reruns the method or a supposedly fixed baseline.

The independent validator does reject false success flags and nonexistent gates. It correctly detects nonminimal outputs. But [the scorer](eval/test/evaluate_circuit_outputs.py) calculates injected-label overlap regardless of validity/minimality, and all those constraints have coefficient zero. Therefore a method failing the task can outrank the reference through other metrics: the padding shortcut has **0/13 minimum diagnoses and positive rank**, while the duplicate shortcut has identical ranked metrics and 0/13 minimum diagnoses. Label copying also dominates the reference in every ranked metric while violating minimality on three instances. There is no validity gate on the rank.

**Failure accounting and method enumeration fail.** Missing/empty rows early-continue, leaving total extra/missing-fault counts and work at zero rather than assigning worst values. Empty output still loses overall in this cohort, but it is incorrectly rewarded on several terms. More seriously, the hidden evaluator restricts discovered artifact files to method keys in the first nonempty public train-score experiment. Clearing all train keys produces no selected methods and a successful test with every `results` empty. All 13 ranked candidate metrics disappear and the specified skip rule gives zero loss. The late-method run proves that an artifact on disk can be omitted from every experiment: see [its metadata](redteam/late_method_shortcut/run_metadata.json). The retained CFaults score is not the absent method's score.

The reference does saturate the **unranked scientific constraints**: overall localized rate/count 100%/13; valid-minimal, all-observation-consistent, all-reported-valid-minimal, and nonempty-output rates 100%; invalid/nonminimal/missing/empty counts zero; all five reported observation localization rates/counts at their slice maxima (4/5/4/4/4). HSD is a legitimate stronger ranked baseline here, rather than a simple baseline clearly below the reference; the all-gates and constant shortcuts are clearly lower, while exhaustive exact search is already sufficient.

**Evidence and next iteration.** [checks.json](redteam/checks.json), generated by [check_evidence.py](redteam/check_evidence.py), checks every command exit status, all 13 seed spreads, reference equality, full diagnosis-set equality, the constraint failure, omissions, and score overwrite. [summary.json](redteam/summary.json) retains every metric contribution and normalization scale. All 25 cases passed both public and restored hidden evaluation. Repair priorities are private held-out circuits/labels with immutable task data and baselines; evaluator-controlled method enumeration and worst-value failure records; an enforced minimum-diagnosis constraint; and measured, trustworthy computational cost on instances large enough to separate enumeration from the intended method. These are findings for the next gym iteration; no gym method, data, scorer, or configuration is changed by this audit.
